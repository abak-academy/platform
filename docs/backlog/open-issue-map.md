# Open issue map

This is a **living, code-facing map** of open platform issues, maintained in the same PR that changes an issue's behavior. GitHub issues hold the requested outcome; this page records what the **code in the relevant commit** does and what still needs proof. It is not a deployment status page or a replacement for the issue's acceptance criteria. Git and PR diffs are its changelog.

## Maintenance contract

- New issue intake is **manual**: the issue creator or maintainer adds a placeholder `unassessed` entry via a reviewed documentation PR when opening an issue. Record its number/link and `issue_updated_at`; do not set `checked_against` or assert code status until someone inspects the code. There is no issue-event bot. If an agent finds an issue missing from this map while starting its work, add that entry in the issue PR and then update it with verified branch evidence before handoff.
- Before an issue-related change, read the issue **and comments** and its entry here. Check whether the issue changed since `issue_updated_at` and whether relevant code changed since `checked_against` (if present). Revalidate the affected behavior; a matching path list alone is not proof that nothing changed.
- In **every PR that works on an issue**, add or update only its affected entries in that PR, before opening it. Record the observed behavior **on the PR branch**, a code/test reference, remaining criteria or runtime proof, the latest issue `updatedAt`, and the commit checked. Use `partial`, `not implemented`, or `uncertain` rather than implying completion without evidence.
- If the PR fully satisfies an issue's agreed criteria and verification, remove its entry **in that same PR** and explain the removal and evidence in the PR body. The base branch retains its entry until merge. A PR opening is not a merge, issue closure, or production rollout; do not assert those from this map.
- If an issue changes outside a code PR, the next issue-related PR refreshes its entry. Do not re-audit all other issues just to bump a global SHA. Never copy secrets, student data, or production-only claims into this client-visible repo.
