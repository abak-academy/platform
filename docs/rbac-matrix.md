# RBAC matrix — `/api/v1/admin`

Ground truth: `backend/internal/server/routes.go:33-333` read against `roleCapabilities` in
`backend/internal/service/rbac.go:13-23`, and `HasCapability` (`rbac.go:33-53`).

`HasCapability(role, required)` returns true when a role's capability list contains `"*"`
(matches anything), an exact match for `required`, or an entry ending `x:*` where `required`
starts with `x:`. The "roles that reach it today" column below is derived mechanically from that
function against each route group's `required` string — not eyeballed.

Roles: `student`, `admin_exam`, `admin_store`, `admin_school`, `super_admin`.

## The `/admin` floor (FR-24 #1, #6)

`v1.Group("/admin")` (`routes.go:33-34`) applies only `handler.JWTMiddleware` — there is **no
admin-role floor**. Any authenticated user, including a `student`, passes this group and reaches
whichever subgroup they hit next; access is entirely decided by what each subgroup opts into below.

Adding an admin-role floor here was **considered and declined for this run**: writes are already
guarded a layer down (service-layer checks below), and a blanket floor would touch every admin
module at once in a slice whose only sanctioned fix is the three `/admin/courses` reads. Recorded
as a known, deliberate posture — not a gap.
